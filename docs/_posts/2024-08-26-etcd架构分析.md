# 概述
etcd即etc distributed，也就是分布式的配置系统，官方描述为：“etcd is a strongly consistent, distributed key-value store that provides a reliable way to store data that needs to be accessed by a distributed system or cluster of machines. ”这段话表明etcd至少具有三个特点：

1. 为分布式系统具有高可靠性。使用Raft协议维持集群中多个节点之间的强一致性，etcd支持从follower读取数据，但是写数据必须通过leader。
2. 具备服务发现功能，该功能基于etcd提供的watch机制，可以对部分键的写操作进行监控，并且返回多个数据版本。
3. 键值存储系统代表数据结构为KV对。

# 模块组成
![image.png](http://pic.kinghno3.top//kinghno3_blog/20240826140152.png)<br />**HTTP LAYER**：监听服务端口，用于接收HTTP(s)网络请求以及返回给客户端网络数据，也可完成集群间的数据通信。<br />**RAFT**：节点间强一致性协议的具体实现<br />**存储模块(Store)**：KV对、WAL、Snapshot的存储实现，同时处理etcd事务，Watch机制的监控和通知等实现。<br />**复制状态机(Replicate State Machine)**：一个分布式复制状态机系统由多个复制状态机组成，复制状态机状态由内部状态变量描述，状态变量只能通过外部修改。每个节点中，通过读取操作日志中的状态修改信息，就可以将复制状态机流转到一个特定的状态。也就是说，各节点操作日志相同，那么复制状态机最后的状态也相同。并且一些服务器故障也不会影响到其他节点对操作日志的正常应用。

# 数据通道
etcd根据传输消息的大小分了两种数据通道，一种是Stream一种是Pipeline。从而避免大消息对小消息的阻塞。<br />Stream用于传输小的消息，比如心跳、日志追加消息，在节点启动后，就跟每个其他节点建立HTTP长连接。内部使用两个Goroutine实现消息的转发。<br />一个从Http消息中读取并解析数据转化为消息结构体，并通过Channel将该转化好的消息传输给Raft模块，另一个Goroutine则负责从Raft模块获取消息写到Stream通道中(HTTP长连接)

Pipeline则用于传输Snapshot这种大消息，建立的是短连接，pipeline可以通过多个Goroutine并发发送消息。

# 数据存储策略
使用“索引加存储”的方式实现，在读取数据时可以通过索引快速获取到各个版本的数据。

为了解决读写锁之间的阻塞，etcd使用了MVCC来管理多版本数据。各版本的可见性是通过修订号revision结构体来维护。revision.main是一个全局递增的更新版本(每次写操作都会递增)，revision.sub以某个事务中的更新次序递增。可以将revision看做一个全局的逻辑时钟，全局中每有修改操作都会单调递增。
```go
type revision struct {
    main int64

    sub int64
}
```

读取key-value的过程： 首先通过Key在索引系统中找到每个KV特有的修订号，然后再使用该修订号找到真正的Value。boltdb是etcd的具体磁盘存储实现。但boltdb也有自己的内存buffer，首先读取会在buffer中二分查询，查不到则在磁盘中读取。

# 数据监控机制
可以使用watch api来使用etcd的监控功能，用于异步监听keys在某个指定版本号后的变化，每一次变化都对应着一个Event结构体。
```protobuf
message Event {
  enum EventType {
    PUT = 0;
    DELETE = 1;
}
  EventType type = 1;
  KeyValue kv = 2;
  KeyValue prev_kv = 3;
}

```
watch是长时间运行的，因此使用gRPC流传输数据，可称为watch流。一方面客户端将建立watch的信息通过流传输到服务端，另一方面服务端将Event传输到客户端。<br />创建Watch所对应的结构体为WatchCreateRequest：
```protobuf
message WatchCreateRequest {
  bytes key = 1;
  bytes range_end = 2;
  int64 start_revision = 3;
  bool progress_notify = 4;

  enum FilterType {
    NOPUT = 0;
    NODELETE = 1;
  }
  repeated FilterType filters = 5;
  bool prev_kv = 6;
}

```
start_revision代表要从哪个修订号开始监听。<br />progress_notify则表示开启Watch流的心跳，否则，如果key很长时间不变动，客户端很难判断是否watch已经断连。
