在数据库初始化，也就是准备好数据库目录、系统表、模版数据库等工作后将启动守护进程Postmaster，作为总控进程。职责是，**针对每个客户端连接都会fork出一个Postgres进程来负责与客户端的互动**，同时也**管理与数据库运行相关的辅助进程**。<br />每个连接都有一个对应的进程来管理，这种多进程设计的好处在于：如果有某个Postgres进程崩溃，不会影响其他客户端命令的执行。
<a name="Wb54n"></a>
# 执行流程
<a name="okmYD"></a>
## 初始化内存上下文
内存上下文用于一种新的内存管理机制，这种管理机制可以防止因为开发人员疏忽于释放内存而导致的内存泄漏问题。<br />具体来说，可以将占用的内存划分到一个个内存上下文中，当某个内存上下文释放时，其内部分配的内存也会被自动释放。<br />这些内存上下文通过树状结构进行组织，兄弟节点或子节点的释放不影响自身，然而节点的释放也会导致其子节点的释放。<br />这种管理方式将对具体内存的管理转换为了对内存上下文的管理，能够更好地控制不同作用域的内存占用情况，同时也避免了内存释放不干净的情况。
<a name="nqsWo"></a>
## 配置参数
配置Postmaster需要的参数，执行配置的模块称为GUC(Grand Unified Configuration)。<br />GUC将命令分为了多类，它们有不同的优先级，可以更好地进行层次管理。<br />主要考虑以下几种参数：

- 默认值：默认值优先级最低，是初始化的参数。
- 配置文件：比如postgresql.conf中的参数，这些参数会覆盖默认值中的相应参数，优先级次之。
- Set语句配置的参数：这些参数只能在当前会话中作用，优先级高于配置文件。
- 命令行参数配置：这些参数优先级最高，无法被其他方式配置的参数覆盖。

配置的顺序为：**初始化默认值 ---> 读取命令行中的配置 ---> 读取并解析配置文件**
<a name="HnQLF"></a>
## 创建监听Socket
PostgreSQL支持TCP、Unix套接字进行网络通信，此处绑定本机网卡IP创建Socket来监听来自客户端的数据。<br />在创建好Socket后，将创建进程间通信使用的共享内存和信号量。
<a name="TkJLR"></a>
## 注册信号处理函数
操作系统支持进程根据不同的信号自行注册不同的处理函数，Postgres用这种特性为不同信号注册不同函数，从而完善对Postgres系统的管理。<br />关注以下几个信号及其处理：<br />SIGHUP：Postmaster接收到SIGHUP信号时重新读取配置文件postgresql.conf，并且通知子进程也重读配置文件。大多数运行参数可以及时生效，然而部分运行参数由于其自身作用原因无法立即生效，比如最大连接数。<br />SIGTERM：优雅结束，Postmaster等待所有子进程完成当前任务后退出系统。<br />SIGINT：向所有子进程发送SIGTERM信号，子进程接收到该信号后回滚事务，最后Postmaster退出系统。<br />SIGQUIT：强制退出系统，Postmaster向子进程发送SIGQUIT信号，立即退出<br />子进程结束时会向Postmaster发送SIGCHLD信号，根据子进程不同以及子进程是否为异常退出等情况所采取的措施也不同。
<a name="oOQNF"></a>
## 启动后台辅助进程
首先启动SysLogger进程，用于收集其他进程的日志。<br />然后启动并初始化其他辅助进程
<a name="TOKWs"></a>
## 装载客户端认证文件
Postmaster进程通过认证文件确定是否要拒绝客户端的访问。<br />文件有pg_hba.conf和pg_ident.conf，其中pg_hba为基于主机的认证文件，其中每一条都是一个规则，一个规则包含了连接类型(TCP?Unix?Ipv4?)、数据库名、用户(可以是all)、主机地址、认证方法。<br />如果认证方法选用ident，也就是基于身份验证，那么就继续参考pg_ident.conf文件确定是否拒绝访问。<br />pg_ident中每一条都是一个映射关系，包括映射名称、系统用户名、要映射到PG中的用户名，比如：
```
mymap   osuser1             pguser1
```
同时，pg_ident.conf中没有体现的是同名映射，比如系统用户名为user，在数据库中也可以使用同名用户进行连接，也就是通过user进行连接
<a name="EkajI"></a>
## 循环监听客户端的连接请求
在Postmaster中循环监听客户端的连接请求，当有请求进入时进行处理，将socket fd、超时参数等信息放入结构体Port中，并检查辅助进程的运行情况是否正常，此后fork出Postgres子进程，继续补充Port中的信息，比如客户端地址、要连接的数据库、用户名等。<br />然后通过客户端相关信息以及认证文件(pg_hba.conf, pg_ident.conf)对用户信息进行认证。<br />此后，客户端通过Postgres进程与数据库进行交互，Postmaster继续监听新连接请求。
